# BRAIN Food Wheel — deployed inspection bundle

Read-only export of https://thebraindiet.org/explore/food-wheel/ on 6 November 2026. This is the actual deployed snapshot, not a regenerated local network. Production merge commit: b4d8f127854ae165e2bcd675a3b475044d63b984. Netlify deployment: 6aedb434fa418ba844b6fd06. See deployment_metadata.json for extraction timestamp and hashes. Embedded scientific source is an earlier, locally modified snapshot; do not confuse it with the deployment commit.

## Files

- network.json: metadata plus exact embedded DATA object. `data.foods`, `data.foodPairs`, `data.network.inventory`, `data.network.connections`, `data.network.interventions`, transformations, source states, proposals, gap ledger and top-source lists are preserved without scientific edits.
- foods.csv: all 90 canonical food IDs, fixed label counts, direct/derived/proposed counts, BRS reach, strategies and rendered font size.
- substances.csv: all 76 inventory records; filter `inclusion=included` for the 68 displayed identities. Excluded entries remain available for diagnosis.
- food_substance_edges.csv: one row per distinct food–substance pair (1,768). `existing=true` identifies 1,750 default pairs. `type` describes composition/derivation status, not PM admission. Observation arrays retain amounts, units, preparation, verification, references and limitations. Proposals may also accompany existing pairs.
- substance_brs_edges.csv: 121 unique substance/system connections. `records` contains individual PM identities, source records, admission/contextual status, limitations and references. Aggregate status must not overwrite underlying record distinctions.
- intervention_edges.csv: intervention-to-identity and composition rows; unmapped behavioural interventions retain a row with no molecular target. Repeated intervention metadata is intentional. Deduplicate by intervention `id` to count interventions; do not count CSV rows as independent interventions. All 87 original intervention objects are also preserved in network.json.
- counting_rules.md and worked_counts.json: exact formulas and five worked calculations, including full lists of target IDs.
- selection_snapshots.json: browser-observed states for six requested selections, plus one failed pointer activation retained transparently. Includes visible/dimmed nodes, displayed food ribbons, highlighted substance/system edges, exact header, and detail-panel HTML/text. Proposals are off in all requested snapshots.
- screenshots/: original viewport PNGs from the live site, not synthetic renders. Some wheel labels fall below the viewport. The complete node/edge and detail-panel capture is in JSON; collapsed detail contents are preserved in HTML even if not visible in the screenshot.
- deployed.html: original fetched production response, including its data and runtime. SHA-256 recorded in metadata. Can be opened offline; external scientific references still require internet. Supporting source tables and scope page are included.
- export_bundle.py: standard-library-only reproduction of the JSON/CSV/count exports from the frozen deployed.html. Does not modify or fetch the website. Browser screenshots are supplied observations, not generated by this script.
- validation.json and SHA256SUMS: checks and file integrity.

## Reading CSV cells

UTF-8 comma-separated text with standard CSV quoting. Structured arrays/objects are JSON strings inside cells: use a CSV parser and then JSON-decode those columns. Do not split on commas manually. Missing/empty amounts are not zero. Numerical values retain their original units/basis; do not sum incomparable observations.

## Reproduction

1. Unzip and verify files with `shasum -a 256 -c SHA256SUMS`.
2. Run `python3 export_bundle.py` inside the bundle to reproduce exports from the frozen HTML. It verifies the HTML hash first. No project checkout or third-party packages are needed.
3. Optionally run `python3 -m http.server 8000` and open `/deployed.html` to inspect the frozen page. Never substitute a fresh live fetch into this bundle without recording a new timestamp, deployment identity and checksum.
4. Browser capture sequence: initial full network; click BRS6; focus the Hormones arc and press Enter; choose salmon-roe, beef, then magnesium from the selectors. Snapshot JSON records exact UI states. A pointer click on the narrow Hormones arc left BRS6 active in one attempt; keyboard activation produced the correct 81-food/one-target state. This is an observed interaction issue, not a proven root cause.

## Interpretation safeguards

Connectivity is not nutrient density, dose adequacy, bioavailability, tissue delivery, clinical efficacy or ADHD benefit. Quantified, presence-only, precursor-derived, contextual and proposed evidence remain distinct. Food quantity never inherits a PM SEC score. Publication of the snapshot did not admit proposed relationships. The exporter does not reappraise science, fix aliases, alter ranking or filter broad system views.

BRS6 actually displays 80 foods through seven targets; magnesium alone reaches 78. Hormones actually reaches 81 foods through one target. These are findings about the implementation, not proposed corrections.

No scientific records, diagram code, admissions, SEC assessments or production deployments were changed for this export.
